## 查询与发布

每次完整发布保存一个知识库代次，包含模型配置、全部已发布文档身份和分块快照。首次建库保存空代次；部分失败和全库重建中途不归档。迁移 6 为已有发布记录建立基线，重复启动不重复归档。

检索在同一 SQLite 写事务内读取发布快照并登记所需物理分块 ID，登记前取得独立的操作系统文件锁。登记提交后才执行 Embedding、向量召回、BM25、重排和引用装配。查询结束先移除租约记录，再释放锁。显式文档或知识库删除先移除可见范围，相关向量等在途查询结束后才物理删除。

活跃请求不按时间强制过期。进程退出或崩溃后，操作系统自动释放锁，可以清理遗留租约；锁文件缺失或无法判断时保留向量。该机制依赖本地文件系统锁语义，不是多主机心跳或分布式写入栅栏。启动清理在独占执行器锁下删除没有元数据引用且可取得锁的 UUID 租约文件；仍被引用的文件留给事务内租约回收。

## 管理操作

启用 API Key 时，查看代次需要 read，回滚与回收需要 admin。默认关闭认证的本地模式仍由部署者限制访问。

| 操作 | 接口 | 输入与结果 |
|---|---|---|
| 查看 | GET `/v1/knowledge-bases/{id}/index-generations` | 当前代次、模型、文档／分块数量、是否需要重建 |
| 预览或回收 | POST `/v1/knowledge-bases/{id}/index-garbage-collection` | `keep_generations` 默认 2，范围 1—100；`dry_run` 默认 true；执行必须给 `expected_generation_id` |
| 回滚 | POST `/v1/knowledge-bases/{id}/index-generations/rollback` | 目标 `generation_id`、`expected_generation_id` 和非空 `reason` |

回收保留最近 N 个完整代次，始终保留当前代次，即使它是较早的回滚版本。保护全部暂存分块、当前发布分块、保留代次及活跃查询。业务上仍保留的历史文档也有结构引用，不会当作垃圾删除。

预览不修改归档、租约或删除待办，返回候选数量、最多 100 个分块样本和查询保护数量。实际执行先在事务内裁剪归档、持久化无结构引用向量的删除待办，再物理删除。查询仍在使用的孤立向量也进入待办，查询结束后处理。预期代次与当前不符时返回 409，要求重新核对。

物理删除失败返回 503，待办保留，重放不调用文档 Embedding。每次删除前在 SQLite 写锁内核对结构引用和查询租约，已重新使用的分块 ID 取消删除。共库 SQLite 复用事务，删除和确认一起回滚；外部向量库先幂等删除再确认，确认失败可再次删除。自动维护在启动、入库、查询完成及每 5 秒执行，每批最多 1000 条；临时失败有限退避，第 5 次阻塞，权限和参数错误直接阻塞。管理员可查看待办、最早时间和错误类型，再显式重放；指标提供待办与阻塞数量。迁移 7 保存重试状态。

## 回滚后的写入

回滚一起切换模型配置、文档正文和引用，不重新计算文档 Embedding。目标不属于该知识库、目标向量缺失、当前代次不符或入库仍在执行时拒绝。原因与代次变化持久保存。显式删除文档使包含它的旧归档失效，不能通过回滚复活已删除资料。

回滚切换查询发布记录，管理中的最新源文档和暂存配置仍保留。因此回滚后拒绝新入库和普通失败重试，显式完成全库重建后才恢复写入。重建时旧发布继续可查，失败批次允许重试。回滚不恢复原 PDF 或业务有效期；旧政策不允许使用时仍须有效期或停用流程。
