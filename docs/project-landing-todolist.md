# pdf inspector 项目落地差距与待办清单

整理日期：2026-10-05
依据：修改版工程问答 93 题、当前项目代码、历史验收报告。
用途：把面试回答中的“默认配置、尚未实现、缺少实测、仅有接口”转成可执行、可验收的任务。

## 先明确当前项目的位置

项目已经有 PDF 解析、任务持久化、按需 OCR、结构化字段与表格、知识库、向量检索、多查询 RRF、可选重排、上下文装配、引用和反馈接口。历史上也有真实 PDF 的解析修复、离线完整流程和独立恢复案例。因此，不能归纳为“没有真实案例”。

真正欠缺的是：**在一个明确业务场景下，使用真实语义模型和人工标注数据，证明回答质量、参数取舍、费用与延迟，并形成真实用户反馈和持续回归。** 现有离线 hash 向量与抽取式回答主要验证工程流程，不能替代这些证据。

学习路线图中部分任务标成“已完成”，表示接口或机制已经存在；并不自动意味着通过真实模型、共享部署、用户试用或容量验收。例如：有反馈 API，仍不等于已有真实反馈闭环；有 Prometheus 输出，仍不等于具备集中监控和线上 P95。

初版状态来自代码和历史报告核对。下方待办保留初版审计记录，后续进度以本节和独立报告为准；没有找到验证记录的事项不直接断言从未做过。

## 优先级与完成规则

| 标记 | 含义 | 完成条件 |
|---|---|---|
| P0 | 核心业务闭环，或目标部署下必须解决的正确性、权限、资源问题 | 指定场景有证据验证；适用的部署阻断项通过检查 |
| P1 | 提高质量、减少费用或增强稳定性 | 有对照结果或故障恢复证据，不能只以新增代码验收 |
| P2 | 由规模和接入需求触发的扩展 | 先证明需要，再决定建设；可以暂缓 |

下面的数字样本规模和实验取值是**建议起点**，不是已完成结果，也不是通用生产标准。验收前先固定业务目标、硬件、模型、成本上限和关键错误口径。P0 条件项只在相应场景适用，例如多人共享需要对象权限；单实例本地演示不必先建多租户与分布式队列。

每项勾选完成时，至少附上：输入版本、配置、执行日期、结果报告、失败样本和相关提交。未获得数据时保持未完成，不能用“接口能调用”代替“效果已验证”。

## 一、业务与效果证据：T01—T05

### T01 选定一个能完整交付的真实业务场景

- [ ] **P0｜现状：流程能力存在，业务收益与用户任务完成证据不足。**
- **要做：** 从已有手册、制度或报价资料中选择一个场景，写清使用者、问题类型、数据更新频率、允许的证据范围与人工复核位置。建议先做“手册参数与使用限制查询”；关键金额自动决策应另设严格核验。
- **验收：** 能展示从上传到答案、来源核对、失败处理的全过程；至少有可追溯的成功、无答案和复核案例。提前给质量、响应时间、成本定目标，不能事后按结果改标准。
- **产物：** 一页场景说明、业务验收表、完整演示步骤。
- **对应问答：** A01、A03、G08、L01。**依赖：** 无。**证据：** S01、S02。

### T02 建立真实、人工核对的评测集

- [ ] **P0｜现状：有来源匹配评测接口，缺少足以支撑业务质量结论的标注证据。**
- **要做：** 使用有权处理的业务 PDF 或公开 PDF，人工标注问题、参考答案、正确文档版本、页码、最小支持片段、关键条件以及是否应拒答。建议先做 20—30 份文档、约 100 个问题的探索集，再根据失败分布扩充。
- **覆盖：** 同义问法、缩写、型号差一位、金额币种、跨页条款、表格行、无答案、矛盾、旧版本和 OCR 遗漏。按文档族划分调参集与保留测试集，避免同一模板近重复样本跨集合泄漏。
- **验收：** 随机抽样复核；分歧有记录；每个参考答案都能回到原页。样本少时报告数量与不确定性，不能宣称通用准确率。
- **产物：** 带版本的数据集、标注说明、复核记录。
- **对应问答：** B09、G02、G04、G06。**依赖：** T01。**证据：** S01、S03。

### T03 接入并验收真实语义 Embedding 与生成模型

- [ ] **P0｜现状：已有模型接口；历史主要验收使用 hash/extractive。**
- **要做：** 固定一个真实语义 Embedding 模型和一个真实生成模型；记录实际模型标识、版本、向量维度、服务地址类别及配置。更换模型时隔离或重建索引，避免混用旧向量。
- **验收：** 完成真实文档入库、检索和问答；验证同义表达与精确词问题、维度异常、批量数量异常、网络失败、流式及非流式调用。模型加载、下载和冷启动分别记录。
- **产物：** 可复现配置、调用契约记录、真实模型端到端报告。
- **对应问答：** B01、B09、E07、H01。**依赖：** T02。**证据：** S01、S04。

### T04 补齐答案质量评测与正确的指标口径

- [ ] **P0｜现状：已有 Recall@K、MRR 与评测样本 P95；来源判分以文档和页码为主。**
- **要做：** 增加最小证据命中、关键字段/单位正确性、答案支持性、引用正确性、应答覆盖率与拒答错误的独立统计。无答案样本单独判分，不把“命中相关页”视为答案正确；存在多个必需证据时检查是否全部覆盖。
- **验收：** 区分“源文遗漏、未召回、重排丢失、上下文截断、生成错误”；同一固定模型和数据能复跑。评测接口已计算的 P95 与真实 HTTP 单请求 P95 分别展示，批量均摊耗时不能当线上测量。

### T05 把项目案例和选型依据整理成可追溯证据

## 二、检索质量与参数依据：T06—T13

### T06 补充真正的词法召回与混合检索

- [ ] **P1｜现状：多查询向量检索 + RRF 已有，BM25 通道未实现。精确词漏检影响业务时进入首批。**
- **要做：** 为相同子块建立 BM25 索引；规定中文分词、型号、编号、连字符和数字的处理方式。向量与 BM25 返回同一块身份，先执行一致的知识库、文档版本与授权过滤，再融合。
- **验收：** 对照 BM25 单路、向量单路、二者融合；覆盖型号差一位、精确编号和同义表达。检查新增、更新、删除、历史查询及重建一致性；把两路与融合后的候选分别保存。
- **产物：** 混合检索功能、维护流程、分题型消融报告。没有收益或成本不合理时允许关闭，不能以功能存在作为效果证明。
- **对应问答：** B03、B05、G04。**依赖：** T02—T04。**证据：** S01、S06。

### T07 为 RRF 的 k 建立项目内实验依据

- [ ] **P1｜现状：函数默认 rank_constant=60；主调用未传入该参数。没有找到本项目调参报告。**
- **要做：** 把 k 暴露到服务配置、评测配置和检索轨迹。先保存相同查询、相同每路候选与排序，比较 k=10、30、60、100；取值只作探索起点。单独测试向量多查询融合与向量/BM25 融合，不能混为同一实验。
- **验收：** 在调参集比较 Recall@K、MRR、可回答证据覆盖与关键问题排名，再在保留集确认。展示互补路、重复改写、单路头部和多路中部命中的案例；记录指标差异与样本数量。
- **产物：** 可配置 k、参数对照表、采用或继续保留 60 的理由。若效果持平，可以保留 60 并如实说明，无需为了面试更换参数。
- **对应问答：** B05、B07。**依赖：** T04；混合通道实验另依赖 T06。**证据：** S06、S07、W01。

### T08 证明多查询改写带来的增益而非只增加候选

- [ ] **P1｜现状：已有规则改写，默认最多 3 路，请求范围 1—5。**
- **要做：** 比较关闭、1/3/5 路；记录每路新增的正确来源、重复父块、查询漂移、Embedding 费用和延迟。检查否定、数字、型号与时间是否保留，识别高度冗余的改写。
- **验收：** 同时报告固定总体候选预算的对照和实际部署预算的对照，避免将增加算力误记为算法收益。对于“并且”拆分的复合问题，最终答案仍须满足原问题全部条件。
- **产物：** 分题型改写报告、别名维护流程与可关闭的配置。
- **对应问答：** B08、D04、D05、G04。**依赖：** T04。**证据：** S06、S07、S08。

### T09 校准子块长度、重叠和父块恢复策略

- [ ] **P1｜现状：子块 1200/1800 字符、重叠 150；父块参考上限 6000 字符，缺少业务最优依据。**
- **要做：** 在保持标题、表格行和章节边界的前提下，比较少量长度方案；分别对照恢复父块与只用子块。检查父块是否带入无关条款、是否在预算内挤掉其他必需证据，以及同父多子去重后是否需要补足不同父块。
- **验收：** 精确字段和解释型问题分别统计；同时看检索、答案支持性、输入 Token 和延迟。超长不可拆表格行有明确处理政策，不以字符上限宣称 Token 硬保证。
- **产物：** 切块与父块策略报告、参数选择记录。
- **对应问答：** B02、B10、C01、C02、C03。**依赖：** T04、T13。**证据：** S09、S10。

### T10 校准重排配置并验证超时后的实际资源行为

- **要做：** 使用相同候选对照开关与少量配置，确认中英文、表格和长限制条款是否被模型输入截断。候选量按实际请求和去重后结果记录。
- **验收：** 报告首位证据、MRR、答案质量、输入截断、额外延迟和回退率；注入连续慢推理，检查等待超时后线程是否继续工作、队列是否积压。需要时增加有界提交、隔离执行与熔断。
- **产物：** 重排质量/资源报告、上线和关闭条件。
- **对应问答：** B04、G04、I14。**依赖：** T04；资源治理联动 T21。**证据：** S11。

### T11 校准证据阈值，补充“相关但不能回答”的判断

- [ ] **P0｜现状：最低证据相似度默认 0.2；没有证据时拒答，证据是否充分主要靠生成提示。**
- **要做：** 用有答案、无答案、相关但不支持、过期、矛盾和缺少条件的样本扫描阈值；对关键业务问题增加条件齐全性检查。模型或语料变化后重新验证，不把融合分数或重排分数当可信概率。
- **验收：** 同时报误答率、过度拒答率和可回答问题覆盖率；报告不同题型与模型的阈值表现。不能通过大量拒答制造高正确率，也不能通过降低阈值填充无关材料。
- **产物：** 阈值报告、拒答理由分类、缺证据时的补充材料提示。
- **对应问答：** B06、H04。**依赖：** T04、T14、T15。**证据：** S04、S10、S12。

### T12 把表格筛选升级为明确的业务查询契约

- [x] **P0（型号、金额业务）/P1（普通文本问答）｜工程实现完成：严格等值、显式包含、数值范围、单位／币种和重复列身份。** 2026-10-05 新增 11 项回归；三种召回路径只把命中行交给问答，取消 PostgreSQL 过滤前候选截断。实际 PostgreSQL 和真实表格准确性待验收，见 [说明](precise-table-query.md)。
- **要做：** 区分精确等值、包含、数值区间和币种/单位归一化；保存稳定列身份，处理重复表头。多个条件必须作用于同一行；拒绝不支持的操作而非静默近似。

- [ ] **P1｜现状：已有文件校验和独立恢复案例；各库及普通文件不天然属于同一时刻快照。**
- **要做：** 采用暂停写入/一致性屏障等适合当前部署的方案，规定备份对象、频率、保留、最大允许数据损失（RPO）和恢复时间（RTO）。真实模型配置、词法索引与将来外部向量库都要有明确恢复政策，不能只打包本地目录。
- **验收：** 使用新目录恢复并让原目录不可用；验证任务、结果、字段、检索、引用和再入库。写入期间备份需检测一致性或限制执行；新版本索引发布与备份的关系有记录。
- **产物：** 备份/恢复操作册、定期演练、实际 RPO/RTO 记录。
- **对应问答：** I09、I12。**依赖：** T17、T30。**证据：** S28。

## 六、由需求触发的扩展：T32—T34

### T32 在容量瓶颈出现后评估 ANN 与父块存储优化

- [ ] **P2｜现状：本地向量以精确扫描为主；父块正文随子块重复保存。**
- **触发：** T28 显示检索扫描或重复父块数据已经造成延迟、内存、数据库体积或备份成本问题。
- **要做：** 分别评估 ANN 与父块独立存储；ANN 使用精确扫描为对照，固定维度及过滤条件测试；父块去重保留版本、引用和读取契约。
- **验收：** 有容量/成本收益且 Recall@K、关键问题和更新一致性不退化；有回退。数据量小而无瓶颈时保持精确扫描即可。
- **对应问答：** B01、C01、I14。**依赖：** T28。**证据：** S13、S09、S27。

### T33 按真实集成需求验证 LangChain、工具与 Agent

- [ ] **P2｜现状：已有 LangChain Runnable 适配和测试/示例；无完整自主 Agent 或 MCP 服务。**
- **触发：** 外部 LangChain 应用、模型客户端或需要动态查证的业务提出明确接入需求。
- **要做：** 优先用当前适配完成一个真实下游应用，核对过滤、正文与来源。需要 MCP 时再封装现有检索/任务能力；需要 Agent 时再增加目标状态、工具契约、预算、终止和恢复；多 Agent 必须有专门职责和实测收益。
- **验收：** 同一问题跨入口的授权、来源与状态一致；异步/异常调用真实验收。Agent 以任务完成率、成本和恢复为标准，不能只展示会调用工具。
- **对应问答：** A02、D01—D05、E04—E07、F01—F06。**依赖：** T15、T19、T25、T29。**证据：** S29。

### T34 在部署规模明确后再引入队列、对象存储和缓存

- [ ] **P2｜现状：单实例本地文件与数据库可运行；分布式基础设施尚未成为当前闭环的必要条件。**
- **触发：** 需要多个执行节点、机器迁移、大量文件、独立扩缩容，或实测存在高重复读取瓶颈。
- **要做：** 每次只引入解决已测瓶颈的一项。共享队列先完成执行身份；对象存储定义文件可见性、清理和下载权限；缓存键绑定授权范围、版本、模型和查询配置，使用权威代次防止旧请求回填。
- **验收：** 网络故障、重复消息、旧执行器回写、旧缓存回填、权限撤销和备份恢复都可控；收益超过运行复杂度。没有触发需求时记“暂缓”，不为凑技术栈补齐。
- **对应问答：** I01—I06、I11、I14。**依赖：** T17、T22、T25、T28、T31。**证据：** S01、S22。
