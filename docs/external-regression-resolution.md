## 1. 问题是什么

`pdf-evals` 是项目指令引用的外部 PDF 提取质量回归套件，不属于应用运行时依赖。其作用是用更多版式的 PDF 和预期输出检查算法变化是否破坏已有内容，包括正文顺序、表格结构、符号、单位及文本完整性。

“兼容”表示样本、预期结果、执行脚本和被测 CLI 适用于该项目版本。目前没有拿到套件，尚未发生实际版本兼容性测试，也没有发现项目因缺少它而无法运行的问题。

项目 [AGENTS.md](../AGENTS.md) 的现行要求是：`Run cargo build --release then bench.py test in that repo before committing.` 因此当前缺口是提交前的额外回归证据，不能通过安装模型、启动 API 或下载任意同名仓库解决。

## 8. 长期方案的具体完成标准

以下是后续实施建议，当前没有改动 AGENTS.md 或 CI：

- **样本与来源：** 复用可分发 fixture，补充缺失的合成样本；记录来源或生成方法、用途及输入哈希。普通公开下载不自动代表允许再分发。
- **预期与断言：** 保护正文顺序、金额和单位、表格行列、字段冲突、符号、OCR 路由及引用页码。期望值来自源内容审查，不由被测版本自动确认。
- **执行方式：** 用一个明确入口串联已有检查并汇总通过、失败、跳过及原因；绑定实际构建产物，失败返回非零状态。离线模式不得偷偷下载模型；缺失必要依赖或 OCR 未执行不能计为通过。
- **有效性：** 在临时副本对关键预期或输出作受控错误注入，确认对应检查会失败；不要在正式基线中保留故意错误。
- **可复现性：** 干净环境按文档可运行核心回归，不依赖个人的 `test_output/`、业务 PDF 或私有绝对路径。大规模私有覆盖只作为额外证据。
- **规则建议：** 本仓库可复现的核心检查作为提交必检；外部 pdf-evals 在取得经确认的来源和版本后作为额外回归执行。缺失时显式记录，取得后发生的真实失败必须审查，不能按“可选”静默忽略。此建议须经明确确认后才替换现行规则。
