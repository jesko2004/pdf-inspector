# 索引原子发布

阶段日期：2026-10-05。发布元数据由本机 SQLite 保存，向量存储仍可选择 SQLite 或 PostgreSQL；本轮实际验证使用 SQLite。

## 对外行为

新文档要等所有分块与批次完成才参与检索；首次入库部分成功时不会公开半份文档。更新已有文档时，准备、处理中断或失败均继续使用上一份完整发布结果。显式重试只处理失败批次，新版完成后切换正文、父块、来源身份及版本可见范围。

请求开始时，在一个数据库读事务内固定模型配置、文档信息和已发布分块。向量、BM25、改写的各路召回及最终引用共用这一份快照，向量查询还限制允许的物理分块 ID。即使查询执行期间发生发布，也不会把旧版正文配上新版文件或引用。

模型或维度重建使用新的物理分块身份。各文档分别完成后，必须等全知识库就绪，在同一事务发布全部快照及模型配置。`index_rebuild_pending` 表示重建尚待发布；失败时查询继续使用旧模型。重建期间拒绝新的入库和另一轮重建，可以显式重试失败批次。显式删除失败文档后，其余文档全部完成时可以发布剩余范围。

显式版本仍支持历史和 `as_of` 查询。未来生效版本已经准备好时，在其生效日之前继续检索当前有效旧版。完整新代次发布只保证更新过程的范围一致，不表示新内容已经通过人工正确性审核；旧政策不允许继续使用时，应通过有效期或停用流程单独控制。

## 持久化与恢复

数据库迁移 5 新增模型发布指针和文档发布快照；旧数据库只为完整 ready 文档建立初始发布记录，不把 partial 文档升级成完整结果。重启时保留原发布指针，不会把重建中单个已经完成的文档提前发布。

同一逻辑文档的普通更新继续复用未变分块的向量；更新过的内容和更换模型使用独立物理身份。旧向量保留供执行中的查询使用，默认检索根据快照排除它们；显式删除文档或知识库会移除所属的全部向量与发布记录。

尚未实现查询租约、按代次安全回收或任意代次的一键回滚。频繁更新会增加本地向量存储占用；不要手工删除仍可能被运行中查询使用的旧向量。显式文档版本保存历史资料，普通同 ID 更新的历史快照只为运行中的请求持有，不能据此宣称具备完整审计回滚。
