# PDF 文档处理与 RAG 后端六阶段任务书

本文档用于记录项目从 PDF 结构化处理到生产级 RAG 服务的六阶段建设任务，并作为后续学习、开发和验收清单。

## 使用约定

- `P0`：形成阶段闭环所必需。
- `P1`：显著提高质量、稳定性或可用性。
- `P2`：生态适配或高级增强，可根据实际需求选择。
- 状态建议使用：`未开始`、`进行中`、`已完成`、`暂缓`。

---

## 第一阶段：可配置 PDF 文档处理后端

### 阶段目标

将底层 PDF 解析能力封装为可被业务系统调用的后端服务，完成任务管理、字段提取、表格结构化、OCR 补全和知识库预处理。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 1 | PDF 解析 API 与任务管理 | P0 | 支持管理系统批量上传和异步处理 PDF | 支持上传、创建任务、查询进度、获取结果、失败重试；任务状态可持久化并在服务重启后恢复 | |
| 2 | 业务字段提取模板 | P0 | 将全文解析结果转换为可直接使用的业务 JSON | 可配置字段名、别名、提取范围、类型、格式和必填规则；返回字段值、状态及来源证据 | |
| 3 | 表格转业务数据 | P0 | 将 PDF 表格转换成可校验、导入和入库的数据 | 表格可转换为 JSON/CSV；支持列名映射、金额与单位标准化、必填列校验和异常标记 | |
| 4 | 按页 OCR 补全 | P0 | 补齐正文可提取但部分附件为扫描页的混合文档 | 自动识别需要 OCR 的页面；只处理目标页并按原页序合并；保留识别方式、置信度和失败页面 | |
| 5 | 知识库入库预处理 | P0 | 为后续 Embedding 和检索生成高质量 Chunk | 按标题和章节切分；保留页码、章节路径和表格完整性；完成页眉页脚清理、低质量过滤和重复 Chunk 合并 | |

### 阶段完成定义

- 其他系统可以通过 HTTP 完成 PDF 上传、处理、查询和结果下载。
- 输出同时包含业务字段、结构化表格、完整 Markdown 和可供检索的 Chunk。
- OCR、表格和 Chunk 质量问题均可观察、可定位。

## 第二阶段：内置知识库

### 阶段目标

将 PDF 任务结果持久化到内置知识库，建立可重试、可增量更新、可切换 Embedding Provider 的向量化流程。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 6 | 建立知识库数据模型 | P0 | 建立知识库内容之间的持久化关系 | 建立 `KnowledgeBase → Document → Chunk → EmbeddingBatch` 关系；记录任务、页码、章节、状态、哈希、错误和更新时间 | |
| 7 | 知识库管理 API | P0 | 支持不同业务资料分库管理 | 提供知识库创建、列表、详情、修改和删除接口；名称冲突和不存在资源返回明确错误 | |
| 8 | 文档入库 API | P0 | 将已有 PDF 处理结果加入指定知识库 | 支持关联已完成的 PDF 任务并触发 Chunk 持久化和向量化；可查询文档、Chunk 和批次进度 | |
| 9 | Embedding Provider 接口 | P0 | 避免业务代码绑定单一模型厂商 | 抽象统一 Embedding 接口；支持离线 Provider 和 OpenAI 兼容接口；严格校验数量、维度和数值合法性 | |
| 10 | 接入向量数据库 | P0 | 实现可用于生产环境的向量持久化 | 本地支持 SQLite；生产支持 PostgreSQL + pgvector；保存向量及知识库、文档、Chunk 和来源元数据 | |
| 11 | 批量向量化与失败重试 | P0 | 降低大文档处理风险和重复计算 | Chunk 分批生成向量；单批失败不阻断其他批次；记录重试次数和错误；只重试失败批次 | |
| 12 | 幂等入库与增量更新 | P0 | 避免重复入库并降低 Embedding 成本 | 使用 PDF 哈希和 Chunk 集合哈希识别重复任务；稳定文档键支持版本更新；仅处理新增或变化 Chunk | |
| 13 | 删除与重新索引 | P0 | 保证元数据和向量生命周期一致 | 删除文档或知识库时同步清理向量；模型、Provider 或维度改变时支持整库重新索引；中断任务可恢复 | |

### 阶段完成定义

- PDF 任务结果可以稳定、幂等地进入指定知识库。
- 向量化失败不会导致整份文档重新处理。
- 文档更新、删除、模型切换和服务重启均不会破坏数据一致性。

## 第三阶段：知识库检索 API

### 阶段目标

建立独立、可评测、可过滤和可追溯的检索内核，为 RAG 问答和外部框架提供稳定能力。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 14 | 向量相似度检索 | P0 | 根据用户问题召回语义相关 Chunk | 查询文本经过当前知识库 Embedding 配置向量化；SQLite 和 pgvector 均支持余弦 Top-K 检索 | |
| 15 | 检索 API | P0 | 对内外提供统一搜索入口 | 提供 `POST /v1/knowledge-bases/{id}/search`；支持查询文本、Top-K、最低相似度并返回检索耗时 | |
| 16 | 元数据过滤 | P0 | 缩小检索范围并减少无关结果 | 支持按文档 ID、重叠页码范围、Chunk 类型和章节路径前缀过滤；组合过滤行为一致 | |
| 17 | 混合检索 | P1 | 提高型号、金额、编号等精确内容的召回率 | 融合向量检索与关键词/BM25 检索；提供可配置权重；在评测集上优于单一检索 | |
| 18 | 重排序 Reranker | P1 | 提高首屏结果的相关性 | 对初次召回候选重新评分；支持可替换 Reranker；记录重排前后排名和耗时 | |
| 19 | 引用结果标准化 | P0 | 为问答和业务页面提供可追溯证据 | 每条结果包含排名、分数、Chunk ID、原文、文件名、页码、章节、文档和任务信息，以及统一 `citation` 对象 | |
| 20 | 检索评测集与指标 | P1 | 量化检索质量并防止迭代退化 | 建立问题—正确文档/页码数据集；输出 Recall@K、MRR、首个相关结果排名、平均延迟和 P95 延迟 | |

### 阶段完成定义

- 在不依赖 LangChain 的情况下，可以独立搜索知识库。
- 每个结果都有可用于前端展示和回答引用的来源信息。
- 每次调整模型、切片或检索策略后都能通过固定评测集比较效果。

## 第四阶段：RAG 问答服务

### 阶段目标

在原生检索能力之上构建有证据、可拒答、可流式输出并兼容主流模型服务的完整 RAG 问答链路。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 21 | LLM Provider 抽象 | P0 | 支持替换云端或本地生成模型 | 定义统一同步和流式生成接口；支持离线证据提取 Provider 与 OpenAI 兼容 Chat Completions 服务；密钥不写入日志 | |
| 22 | RAG 问答 API | P0 | 将查询、检索、上下文组装和生成形成闭环 | 提供 `POST /v1/knowledge-bases/{id}/ask`；复用检索过滤条件；返回问题、回答、模型、耗时和来源 | |
| 23 | 上下文预算管理 | P0 | 防止上下文超过模型限制并控制成本 | 根据估算 Token 按检索排名选择 Chunk；超长末尾 Chunk 可截断；返回预算、实际使用量和截断状态 | |
| 24 | 引用与证据返回 | P0 | 让回答可以核验和定位原文 | Prompt 要求仅依据证据回答；接口独立返回实际使用的文档、页码和章节引用，不依赖模型自行生成的引用 | |
| 25 | 无证据拒答 | P0 | 降低幻觉和无意义模型调用 | 没有结果达到证据阈值时返回固定拒答；不调用 LLM；引用数组为空并标记 `refused` | |
| 26 | 流式回答 | P1 | 改善长答案的首字响应体验 | `stream=true` 返回 SSE；依次发送 `metadata`、`token`、`done`，异常发送 `error`；关闭代理缓冲 | |
| 27 | LangChain 轻量适配层 | P2 | 让现有检索能力进入 LangChain Chain、Tool 和 Agent 生态 | 作为可选依赖提供 Retriever；将搜索结果转换为 LangChain `Document`；支持同步/异步调用和过滤；不得重写核心入库、检索与问答逻辑 | |

### 阶段完成定义

- 有证据时能够生成带来源的回答，无证据时能够稳定拒答。
- 上下文选择、模型调用和生成耗时均可观察。
- 流式和非流式接口具有一致的证据与拒答语义。
- LangChain 仅作为可选生态适配层，不成为核心运行依赖。

## 第五阶段：生产化与多租户

### 阶段目标

补齐系统上线后的权限、扩展性、数据迁移、监控、成本控制和灾难恢复能力。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 28 | API Key 与权限认证 | P0 | 防止未授权访问和数据修改 | 所有知识库、文档、检索和问答接口支持认证；区分只读、写入和管理权限；敏感操作可审计 | 已完成：Bearer/X-API-Key、三级角色、审计 API |
| 29 | 多租户隔离 | P1 | 支持多个用户、部门或客户共享服务 | 数据模型包含租户边界；所有读写查询强制租户过滤；跨租户访问测试必须失败 | |
| 30 | Redis 与持久化任务队列 | P1 | 支持多实例和长任务稳定执行 | 解析、OCR、Embedding 和重新索引进入持久化队列；支持重试、超时、并发控制和 Worker 横向扩展 | |
| 31 | 对象存储 | P1 | 消除对单机文件系统的依赖 | 支持 MinIO/S3 保存原始 PDF 和结果；使用稳定对象键；失败上传可清理；下载权限受控 | |
| 32 | 数据库迁移机制 | P0 | 保证版本升级时数据结构可控 | 使用 Alembic 或版本化迁移脚本；支持升级、回滚或明确的不可回滚说明；旧数据升级测试通过 | 已完成：SQLite 版本账本、启动校验、基线迁移测试 |
| 33 | 监控与链路追踪 | P1 | 快速定位性能和可靠性问题 | 记录解析、OCR、Embedding、检索和 LLM 耗时；统计错误率、队列深度、Token 和拒答率；支持请求关联 ID | 已完成：Prometheus 指标、结构化日志、Request ID |
| 34 | 限流与成本控制 | P1 | 防止资源滥用和模型费用失控 | 限制上传大小、并发任务、检索/问答频率、上下文和输出 Token；超限返回明确错误 | 已完成：频率、并发、上传与 Token 上限 |
| 35 | 备份与恢复 | P1 | 降低数据库或存储故障风险 | 定期备份元数据、向量和对象文件；记录恢复步骤；通过实际恢复演练验证一致性 | 已完成：一致性备份、校验、空目录恢复与演练测试 |

### 阶段完成定义

- 服务具备明确的身份、权限和租户边界。
- 长任务可以跨进程恢复并支持横向扩展。
- 关键性能、错误和成本指标可观测，数据可备份和恢复。

## 第六阶段：高级检索与持续优化

### 阶段目标

围绕复杂文档、检索质量、历史版本和用户反馈建立差异化能力，并形成持续评测和优化闭环。

| 序号 | 任务 | 优先级 | 作用 | 验收标准 | 状态/学习记录 |
|---|---|---:|---|---|---|
| 36 | 表格感知检索 | P1 | 提高金额、型号、参数和表格行问题的准确率 | 建立表头、行、列和单元格上下文；支持结构化条件与语义联合检索；回答引用保持表格关系 | |
| 37 | 查询改写与多路召回 | P1 | 提高口语化、缩写和复杂问题的召回率 | 将问题生成多个受控查询；并行召回后去重融合；限制额外调用次数和延迟；通过评测证明收益 | |
| 38 | 父子 Chunk 检索 | P1 | 同时兼顾精确匹配和完整上下文 | 小 Chunk 用于召回，父级 Chunk 用于生成上下文；保留父子关系、页码和章节；控制重复上下文 | |
| 39 | 文档版本与时间过滤 | P2 | 避免回答引用过期制度或旧版手册 | 保存文档版本、生效和失效时间；支持按时间检索；默认优先有效版本；历史引用可追溯 | |
| 40 | 用户反馈闭环 | P2 | 使用真实反馈持续优化检索与回答 | 记录答案评价、有效/无效引用和纠正内容；形成脱敏评测样本；支持比较优化前后 Recall、MRR、拒答率和回答质量 | |

### 阶段完成定义

- 表格、复杂问题和长章节场景的检索质量有可量化提升。
- 文档版本变化不会导致默认引用过期资料。
- 用户反馈可以转化为评测数据并用于下一轮检索和提示词优化。
